# 必須キーワード辞書 生成・運用 SOP

> 関連Issue: #175 (P1-A-1) / 担当: ai-engineer
> 関連設計書: `14_AfternoonAIScoring_Rubric.md`, `15_AfternoonScoringAPI_v2.md`

## 1. 目的

午後試験（系統A: 記述式）AI採点における **「必須キーワード」の根拠を監査可能にする** ためのSOPを定める。
辞書 (`packages/shared/src/scoring/keywords/dictionary.ts`) に登録される全キーワードは、ティア・ソース・エビデンスを必須メタデータとして持つ。

## 2. ティア定義

| Tier | 根拠ソース | 必須度 | 採点での扱い | 既定 importance |
|---|---|---|---|---|
| **T1** | IPA公式採点講評・公式解説で加点要件と明記された語 | 必須 | missing 時に keyword_coverage を大幅減点 | 1.0 |
| **T2** | IPA公式解答例の主語/目的語、および主要対策本3冊で共通出現する語 | 必須 | missing 時に減点 | 0.8 |
| **T3** | 主要解説書3冊中2冊以上で言及される専門用語 | 推奨 | missing 時に軽減点 | 0.4 |
| **T4** | LLMが模範解答から抽出した未レビュー候補 | 参考 | 採点には使わずプロンプトヒントのみ | 0.0 |

## 3. 必須メタデータ

```ts
{
  primary: '多要素認証',
  synonyms: ['多段階認証', 'MFA'],
  tier: 'T1',
  source: {
    type: 'ipa_official',
    refs: ['IPA-AP-2023S-PM-Q1-講評.pdf §2 加点要件'],
  },
  evidence: 'IPA講評で「多要素認証への言及を加点要件」と明記',
  reviewedBy: 'ai-engineer-A',
  reviewedAt: '2026-04-21',
}
```

- `source.refs` には **具体的なファイル名・書籍名+ページ** を記載（曖昧な参照は不可）
- `evidence` には「なぜ必須と判定したか」を1文で記述
- T1/T2 は `reviewedBy` 必須

## 4. 辞書生成パイプライン

```
┌─────────────────────────────────────────────────────────┐
│ Step 1: 一次ソース収集                                    │
│  - IPA公式 採点講評 PDF                                   │
│  - IPA公式 解答例                                         │
│  - 主要対策本 3冊以上 (TAC / 翔泳社 / iTec 等)            │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│ Step 2: 自動抽出                                          │
│  - LLM (gpt-4o 等) で講評・解答例から候補語抽出           │
│  - 抽出結果は T4 として暫定登録                           │
│  - スクリプト: scripts/scoring/extract-keyword-candidates │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│ Step 3: 人手レビュー (ai-engineer)                       │
│  - 講評で加点要件と明記 → T1                             │
│  - 公式解答例の主要句 + 対策本3冊共通 → T2               │
│  - 解説書2冊以上で言及 → T3                              │
│  - 上記いずれにも該当しない → T4 維持 or 削除            │
│  - 各エントリに source.refs と evidence を必須記入       │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│ Step 4: PR + CI 検証                                      │
│  - dictionary.ts へ commit                                │
│  - CI が以下を検証 (lint:dictionary):                     │
│    - tier / source / evidence の必須欠損なし              │
│    - T1/T2 は reviewedBy 必須                             │
│    - source.refs が空でない                               │
│  - レビュアー: ai-engineer + 試験区分担当者               │
└─────────────────────────────────────────────────────────┘
```

## 5. 採点ロジックとの連携

`detectMatchedKeywords()` はティア別に matched/missing を返す:

```ts
{
  matched: ['多要素認証'],
  missing: ['権限昇格', 'SIEM'],
  byTier: {
    T1: { matched: ['多要素認証'], missing: [] },
    T2: { matched: [], missing: ['権限昇格'] },
    T3: { matched: [], missing: ['SIEM'] },
    T4: { matched: [], missing: [] },
  }
}
```

バックエンド (#176) はこの結果を以下のように使う:
- **T1 missing**: keyword_coverage スコアを 30 点以上減点
- **T2 missing**: 1件あたり 10 点減点
- **T3 missing**: 1件あたり 3 点減点
- **T4**: 採点には影響させず、LLMプロンプトの `参考キーワード` 欄にのみ含める

## 6. ガバナンス

- 辞書変更は必ず PR レビューを通す（直接 main コミット禁止）
- 四半期ごとに ai-engineer が辞書全体を棚卸し（出題傾向の変化に対応）
- ユーザーから「キーワード判定がおかしい」フィードバックがあった場合、該当エントリの `evidence` と `source.refs` を再確認し、必要に応じてティアを下げる or 削除
