# 必須キーワード辞書 生成・運用 SOP

> 関連Issue: #175 (P1-A-1) / 担当: ai-engineer
> 関連設計書: `14_AfternoonAIScoring_Rubric.md`, `15_AfternoonScoringAPI_v2.md`

## 1. 目的

午後試験（系統A: 記述式）AI採点における **「必須キーワード」の根拠を監査可能にする** ためのSOPを定める。
辞書 (`packages/shared/src/scoring/keywords/dictionary.ts`) に登録される全キーワードは、ティア・ソース・エビデンスを必須メタデータとして持つ。

## 2. ティア定義（公開情報限定）

> **重要**: 著作権リスク回避と辞書再現性確保のため、**市販書籍からの直接抽出は採用しない**。
> ソースは「IPA公式（公開・引用許諾範囲）」または「自社蓄積データ」に限定する。

| Tier | 根拠ソース | 必須度 | 採点での扱い | 既定 importance |
|---|---|---|---|---|
| **T1** | IPA公式採点講評で加点要件と明記された語（公開PDF） | 必須 | `keyword_coverage` を 1件あたり **25点減点** | 1.0 |
| **T2** | IPA公式解答例の主語/目的語として直接出現する語（公開PDF） | 必須 | `keyword_coverage` を 1件あたり **12点減点** | 0.8 |
| **T3** | 自社プラットフォームのユーザー解答コーパスで正答群に頻出する語（自社データ） | 推奨 | `keyword_coverage` を 1件あたり **4点減点** | 0.4 |
| **T4** | LLMが**IPA公式解答例から**抽出した未レビュー候補 | 参考 | 採点に影響させず、LLMプロンプトの「参考」欄にのみ含める | 0.0 |

### なぜ書籍を採用しないか
1. **著作権リスク**: 市販対策本の頻出語抽出は引用範囲を超える恐れがある
2. **再現性**: 第三者が辞書を再生成・検証できる必要がある（書籍は購入が必要）
3. **更新性**: IPA公式PDF と自社コーパスは API/クエリで自動更新可能

## 3. 必須メタデータ

```ts
{
  primary: '多要素認証',
  synonyms: ['多段階認証', 'MFA'],
  tier: 'T1',
  source: {
    type: 'ipa_review',  // 'ipa_review' | 'ipa_model_answer' | 'internal_corpus' | 'llm_extracted'
    refs: ['IPA公式採点講評 AP 2023春 午後 問1 §2 加点要件 (https://www.ipa.go.jp/...)'],
  },
  evidence: 'IPA講評で「多要素認証への言及を加点要件」と明記',
  reviewedBy: 'ai-engineer-A',
  reviewedAt: '2026-04-21',
}
```

- `source.type` は `ipa_review | ipa_model_answer | internal_corpus | llm_extracted` の4択
- `source.refs` には **公開PDFのタイトル+セクション+URL**、または **自社コーパスのクエリID** を記載
- `evidence` には「なぜ必須と判定したか」を1文で記述
- T1/T2/T3 は `reviewedBy` 必須

## 4. 辞書生成パイプライン（公開情報のみ）

```
┌─────────────────────────────────────────────────────────┐

│  - IPA公式 試験要綱・シラバス                             │
│  - 自社プラットフォームのユーザー解答コーパス              │
│    (Postgres: answer_submissions WHERE auto_score>=80)   │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│ Step 2: 自動抽出                                          │
│  - LLM (gpt-4o 等) で IPA公式PDF から候補語抽出           │
│  - 自社コーパスから TF-IDF で正答頻出語を抽出             │
│  - 全て T4 として暫定登録（出典タグ付き）                 │
│  - スクリプト: scripts/scoring/extract-keyword-candidates │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│ Step 3: 人手レビュー (ai-engineer)                       │
```

## 5. 採点ロジックとの連携（ティア活用箇所）

ティアは **データ構造ではなく、以下4つの動的振る舞いに使われる** ことで価値を持つ。

### 5.1 採点時：`keyword_coverage` スコア算出

`scoreKeywordCoverage()` (in `aggregator.ts`) がルールベース下限値を決定論的に算出：

```
score = max(0, 100 - 25*|T1miss| - 12*|T2miss| - 4*|T3miss|)
```

LLM 観点スコアと本値の **min** を最終 `keyword_coverage` とする：
```
final = min(llm_score, scoreKeywordCoverage(matchResult).score)
```
これにより「LLM が緩く採点しても T1/T2 欠落は確実に減点される」を保証。

### 5.2 LLMプロンプト時：ティア別グルーピング

`buildShortAnswerPrompt()` は `requiredKeywords: KeywordEntry[]` を受け取り、
ティア別ラベル付きで LLM に注入：
- 【最重要・IPA公式講評の加点要件】 ← T1
- 【必須・IPA公式解答例の主要句】 ← T2
- 【推奨・自社統計の頻出語】 ← T3
- 【参考・LLM抽出候補】 ← T4

### 5.3 UI 表示時（#178/#179 への申し送り）

採点結果ページで「不足キーワード」を表示する際、ティア別バッジ：
- **T1 missing → 赤バッジ「最重要」** + 学習リソースへの導線
- **T2 missing → 橙バッジ「必須」**
- **T3 missing → グレーバッジ「推奨」**
- T4 は表示しない

### 5.4 学習進捗集計時（#187 への申し送り）

ユーザーごとに T1 hit率 / T2 hit率を集計し、「公式必須キーワード習得度」を可視化。
T4 は集計対象外（未レビューのため）。

## 6. ガバナンス

- 辞書変更は必ず PR レビューを通す（直接 main コミット禁止）
- 四半期ごとに ai-engineer が辞書全体を棚卸し（IPA公式PDF更新・コーパス再集計）
- 自社コーパス由来の T3 は3ヶ月ごとに再集計し、出現率が閾値を下回れば T4 へ降格
- ユーザーから「キーワード判定がおかしい」フィードバックがあった場合、該当エントリの `evidence` と `source.refs` を再確認し、必要に応じてティアを下げる or 削除
- **書籍からの抽出禁止**: PRレビュー時に `source.refs` に出版社名・書名が含まれる場合は差し戻し
