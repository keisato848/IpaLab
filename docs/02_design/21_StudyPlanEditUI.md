# 学習計画 編集UI 設計書

> 関連Issue: #189 (P2-A-3) / 担当: ux-designer + frontend-engineer
> 依存: #188 (再計画エンジン)

## 1. 目的

ユーザーが「休む日」「集中日」を簡単に設定でき、変更前後のdiffを視覚的に確認 → 取り消し可能な編集UIを実装する。AIに任せきりではなく "ユーザーが主導権を持つ" 体験を実現する。

## 2. 主要ユースケース

| UC | 内容 |
|---|---|
| UC-1 | 「明日は予定があるので休みたい」 → 1タップで休日指定 → 自動再計画 |
| UC-2 | 「週末は集中したい」 → 集中日指定（×1.5 枠） |
| UC-3 | 「特定タスクを別の日に動かしたい」 → ドラッグ&ドロップ |
| UC-4 | 「やっぱり元に戻したい」 → 取り消し（最大 5 ステップ） |

## 3. 画面構成

### 3.1 カレンダービュー（メイン）
```
┌──────────────────────────────────────┐
│ < 2026年 5月 >          [一覧]│[編集]│
├──────────────────────────────────────┤
│ 日 月 火 水 木 金 土                  │
│  -  -  -  -  1  2  3                  │
│       [3h] [3h]                       │
│  4  5  6  7  8  9 10                  │
│ [休] [3h] [3h] [3h] [集] [3h] [試験]  │
└──────────────────────────────────────┘
```

各セル：日付 / 学習予定時間 / ステータスバッジ（休日 / 集中日 / 試験日）

### 3.2 タスク詳細パネル（右サイド or モーダル）
- 選択日のタスク一覧
- 各タスク：分野・所要時間・優先度・「移動」「スキップ」ボタン

### 3.3 変更プレビュー
- ユーザー操作 → 即座に再計画API呼び出し → diff表示
- diff: 移動されたタスク・挿入されたタスク・押し出されたタスク
- 「適用する」「やめる」ボタン

### 3.4 取り消し履歴
- ヘッダに「↶ 取り消し」「↷ やり直し」ボタン
- 直近 5 ステップを保持

## 4. インタラクション設計

- **休日指定**: 日付を長押し → トグル
- **集中日指定**: 日付ダブルタップ → トグル
- **タスク移動**: ドラッグ&ドロップ（モバイル: 長押し → 移動先タップ）
- **取り消し**: `Cmd+Z` / ボタン

## 5. プレビュー UX

```
[操作]
  ▼
[ローディング 0.3s]  「再計画中...」
  ▼
[プレビュー表示]    「3 件のタスクが移動されます」
  ┌─────────────────┐
  │ 移動: A → 5/8    │
  │ 移動: B → 5/9    │
  │ 押出: C → 5/15   │
  └─────────────────┘
  [適用する] [やめる]
  ▼
[適用完了]          「計画を更新しました」
```

## 7. 状態管理

- 編集中の計画は **ローカル State** + 履歴スタック
- 「適用」で初めてサーバへ永続化（PATCH /api/study-plan）
- 楽観的更新は行わない（diff 確認が価値）

## 8. アクセシビリティ

- カレンダーセルはキーボード操作可能（矢印キー）
- 各セルに `aria-label`（例: "5月8日、集中日、3時間予定"）
- スクリーンリーダ向け diff 読み上げ

## 9. レスポンシブ

- モバイル: 週ビューを基本、月ビューはピンチアウト
- デスクトップ: 月ビュー + サイドパネル

## 10. テスト

- 操作 → プレビュー → 適用のフロー E2E
- 取り消し・やり直しの動作テスト
- a11y（axe-core）パス

## 11. DoD

- 取り消し可能（最低 5 ステップ）
- レスポンシブ動作確認
