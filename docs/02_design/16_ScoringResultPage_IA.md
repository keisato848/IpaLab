# 採点結果ページ 情報設計・UIリデザイン書

> 関連Issue: #177 (P1-A-3) / 担当: ux-designer
> 関連実装: #178, #179

## 1. デザインゴール

- **3秒で「総合点と納得感」が伝わる**（記述式）/ **3秒で「ランクA-D」が伝わる**（論述式）
- **30秒で「なぜその点数か」が理解できる**
- **1分で「次にやるべきこと」が見える**
- **記述式と論述式は別レイアウト**として設計する（情報量・粒度が根本的に異なるため）

## 2. 情報階層（上から）

> **重要**: 系統A（記述式）と系統B（論述式）でレイアウトを分岐する。
> ルーティング: `result.format === 'essay' ? <EssayResultLayout/> : <ShortAnswerResultLayout/>`

### 2.A 系統A：記述式レイアウト

#### Layer 1: ヘッダ（First View / 高さ ~30vh）
- 総合スコア（大きく / アニメーション）
- 設問配点に対する達成率（円形プログレス）
- ステータスバッジ：合格圏 / 要復習 / 弱点あり

#### Layer 2: 観点別スコア・カード（4枚）
- 観点名 / スコア（0-100） / 配点比率
- 加点・減点の根拠テキスト（2文以内）
- 観点ごとに色分け（acc: 緑 / warn: 橙 / weak: 赤）

#### Layer 3: 模範解答との差分（折りたたみ）
- 並列ビュー（左: ユーザー解答 / 右: 模範解答）
- ハイライト：✅ 一致 / ➕ 不足 / ➖ 過剰 / 🔄 言い換え
- アクセシビリティ: 色のみに依存しないアイコン併用

#### Layer 4: アクション（Next Step）
- プライマリ：「弱点を補う演習を始める」（→ #186 で実装）
- セカンダリ：「もう一度解く」「設問解説を読む」
- 「採点に納得しましたか？」👍/👎 (→ #180)

### 2.B 系統B：論述式レイアウト

#### Layer 1: ヘッダ（First View）
- **A/B/C/D ランクを大きく表示**（合否一目）
- 総合スコア（参考値）+ 設問ア・イ・ウの **合計字数**（要件遵守の可視化）
- 試験区分・推定所要時間

#### Layer 2: 設問ア・イ・ウ タブ
```
[ 設問ア (B / 72点) | 設問イ (B / 65点) | 設問ウ (C / 58点) ]
```
- 各タブ内に **6観点のレーダーチャート + 観点カード**
- 観点ごとに：スコア / 根拠 / **解答からの引用ハイライト** / 改善ヒント

#### Layer 3: 字数バー（常時表示）
```
設問ア: ████████░░  720/800字 ✓
設問イ: █████████░ 1480/1600字 ✓
設問ウ: ████░░░░░░  480/1200字 ⚠ 字数不足
```

#### Layer 4: 全体フィードバック
- **強み (3点)** / **弱み (3点)** / **次に取り組むべきこと (3点)**
- 論述式は1問の重みが大きいため、定性フィードバックを重視

#### Layer 5: アクション
- 「論述の書き方ガイドを読む」
- 「同テーマの過去問にチャレンジ」
- 「採点に納得しましたか？」👍/👎

## 3. レスポンシブ

- **モバイル (< 768px)**: 観点カードを縦積み・差分はタブ切替
- **タブレット (768-1024px)**: 観点カード 2x2
- **デスクトップ (≥ 1024px)**: 観点カード 4列・差分は左右並列

## 4. ライティング指針

- **ポジティブ・建設的**：「できなかった」より「次は◯◯を意識すると伸びる」
- **専門用語は最小限**：必要時はツールチップで補足
- **数字＋一言**：「78点 / キーワードは7割網羅。論理構造に伸びしろあり」

## 5. ストリーミング表示の演出

- 観点ごとに到着順でカードがフェードイン
- 全観点到着後、総合スコアが 0→最終値 へカウントアップ
- ローディング中は「採点中...」ではなく「解答を読んでいます」「論理構造を確認しています」と進行を可視化

## 6. アクセシビリティ

- WCAG 2.1 AA 準拠
- 色だけでなくアイコンで状態表現
- キーボード操作で全機能に到達可能
- スクリーンリーダ向け aria-live でストリーミング更新を通知
