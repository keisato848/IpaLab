# 模範解答との差分ハイライトUI 設計書

> 関連Issue: #179 (P1-A-5) / 担当: frontend-engineer
> 依存: #177 (情報設計)
> **改訂履歴**: v1.1 適用範囲を **系統A（記述式）に限定** と明記

## 1. 目的

ユーザー解答と模範解答の差分を、視覚的・直感的に把握できるUIを実装する。色だけに依存しないアクセシブルな設計とする。

## 1.1 適用範囲

- **対象: 系統A（記述式）のみ**（AP午後 / SC午後 / PM・SA・ST午後I）
- 系統B（論述式）は **模範解答との単純差分が成立しない**（解答が多様で正解が一意でない）ため、本UIの対象外。
  - 論述式は #177 §2.B で定義する **「観点別の引用ハイライト + 改善ヒント」** を別途使用する。

## 2. 差分カテゴリ

| カテゴリ | 意味 | アイコン | 色 (デフォルト) | 色 (色覚多様性) |
|---|---|---|---|---|
| `match` | 模範解答と一致 | ✅ | green-500 | パターン (実線) |
| `missing` | ユーザー解答に不足 | ➕ | orange-500 | パターン (点線) |
| `extra` | ユーザー解答に過剰 | ➖ | red-500 | パターン (波線) |
| `rephrasing` | 言い換えで意味は近い | 🔄 | blue-500 | パターン (二重線) |

## 3. 差分計算アルゴリズム

### バックエンド側 (#176 内で実施)
1. 形態素解析（kuromoji）でトークン化
2. キーワードマッチ（必須キーワード辞書照合）
3. LLM ベースの「意味的言い換え」検出（オプション）
4. `ModelAnswerDiff` 構造で返却（→ #175 §6）

### フロントエンド側
- バックエンドから受け取った構造をそのまま描画
- フロントでの追加 diff 計算は行わない（コスト・一貫性のため）

## 4. UI レイアウト

### デスクトップ (左右並列)
```
┌──────────────────┬──────────────────┐
│ あなたの解答      │ 模範解答          │
│                   │                   │
│ [✅ AAA] [➖ BBB] │ [✅ AAA] [➕ CCC] │
│                   │                   │
└──────────────────┴──────────────────┘
```

### モバイル (タブ切替)
```
[ あなた | 模範解答 | 差分一覧 ]
```

### 差分一覧タブ
- 「不足キーワード」「言い換え候補」をリスト表示
- それぞれにツールチップで詳細

## 5. インタラクション

- ハイライト範囲をホバー → 対応する反対側がスクロール＆強調
- アイコンクリック → 詳細ポップオーバー（"なぜ不足と判定されたか"）

## 6. アクセシビリティ

- 各ハイライトに `aria-label`（例: "不足: データベース"）
- 色覚多様性モード（ユーザー設定 or `prefers-contrast`）でパターン切替
- キーボード操作：`Tab` で各ハイライト、`Enter` で詳細展開

## 7. パフォーマンス

- 解答が長文 (1000字超) の場合は仮想スクロール検討
- 差分要素は memo 化
