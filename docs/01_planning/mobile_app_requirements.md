# シカクノ モバイルアプリ 要件定義書

**作成日**: 2026-06-11  
**バージョン**: 1.1  
**ステータス**: Phase 1 要件定義

---

## 1. プロジェクト概要

### 1.1 目的

IPA試験学習アプリ「シカクノ」のAndroid版（Google Play）を開発する。  
Web版の全機能を移植し、オフライン対応とクラウド同期を実現する。

### 1.2 スコープ

| 項目 | 内容 |
|------|------|
| **対象プラットフォーム** | Android（Google Play）、将来的にiOS対応予定 |
| **機能範囲** | Web版全機能の移植 |
| **オフライン対応** | 問題表示、学習履歴のローカル保存、次回接続時に同期 |
| **認証** | GitHub OAuth, Google OAuth, ゲスト利用 |
| **リリース戦略** | クローズドβ → 一般公開の段階的リリース |

### 1.3 制約条件

- 開発リソース: 1名
- Google Play Developer アカウント: 取得済み
- 既存インフラ（Azure, Cosmos DB, Gemini API）を最大限活用

## 2. 機能要件

### 2.1 機能一覧

Web版の機能を以下のように分類する。

| ID | 機能名 | 優先度 | オフライン | 備考 |
|----|--------|--------|-----------|------|

### 2.2 機能詳細

#### F-01: 認証

**概要**: ユーザー認証とセッション管理

**要件**:
- GitHub OAuth によるログイン
- Google OAuth によるログイン
- ゲスト利用（デバイスローカルにデータ保存）
- セッション永続化（自動ログイン）
- ログアウト

**受け入れ基準**:
- [ ] 各OAuthプロバイダーでログインが完了する
- [ ] ゲストとしてアプリを利用開始できる
- [ ] アプリ再起動後もログイン状態が維持される
- [ ] ログアウトでセッションがクリアされる

**技術的考慮事項**:
- `expo-auth-session` でOAuth実装
- `expo-secure-store` でトークン安全保存
- Web版のNextAuth APIを再利用 or モバイル向け認証エンドポイント新設

---

#### F-02: ダッシュボード

**概要**: 学習進捗の可視化と目標管理

**要件**:
- 月間学習進捗カード（回答数、正答率）
- ヒートマップ（日別学習量）
- パフォーマンス分析（分野別正答率）
- 月間目標設定・編集
- 学習計画への導線

**受け入れ基準**:
- [ ] 月間の学習統計が表示される
- [ ] ヒートマップで過去30日間の学習量が視覚化される
- [ ] 分野別の正答率が表示される
- [ ] 月間目標の設定・変更ができる

**オフライン対応**:
- キャッシュされた統計データを表示
- オンライン時に最新データを取得

---

#### F-03: 試験一覧

**概要**: 受験可能な試験の一覧表示

**要件**:
- 年度・種別ごとの試験一覧
- 受験済み/未受験のステータス表示
- 試験種別の説明（午前/午後、SC/PM等）

**受け入れ基準**:
- [ ] 年度・種別でフィルタリングできる
- [ ] 各試験の受験状況が表示される
- [ ] 試験詳細（問題数、制限時間）が確認できる

**オフライン対応**:
- 試験メタデータをローカルにキャッシュ

---

#### F-04: 午前問題演習

**概要**: 4択マークシート形式の午前試験

**要件**:
- 問題表示（テキスト、図表、数式KaTeX対応）
- 4択ラジオボタン
- 解答送信・採点
- 解説表示
- 正答率統計表示（設定で切替可能）
- 問題間ナビゲーション（前/次/一覧）

**受け入れ基準**:
- [ ] 問題文と選択肢が正しく表示される
- [ ] 図表・数式がレンダリングされる
- [ ] 解答が記録される
- [ ] 採点結果と解説が表示される
- [ ] 問題間を移動できる

**オフライン対応**:
- 問題データを事前ダウンロード
- 解答をローカルに一時保存 → オンライン時に送信

---

#### F-05: 午後問題演習（短文回答）

**概要**: テキスト入力形式の午後試験

**要件**:
- 問題表示
- テキスト入力エリア
- 解答送信・AI採点
- 採点結果表示（スコア、フィードバック）
- 模範解答表示

**受け入れ基準**:
- [ ] 問題文が正しく表示される
- [ ] テキスト入力が可能
- [ ] AI採点結果が表示される
- [ ] 模範解答と比較できる

---

#### F-06: 午後問題演習（論述）

**概要**: 原稿用紙形式の論述試験

**要件**:
- 問題表示
- 原稿用紙UI（マス目、文字数カウント）
- 解答送信・AI採点
- 採点結果表示（スコア、観点別評価）
- 模範解答表示

**受け入れ基準**:
- [ ] 原稿用紙UIが正しく表示される
- [ ] 文字数がリアルタイムでカウントされる
- [ ] AI採点で観点別フィードバックが表示される

---

#### F-07: AI採点

**概要**: Gemini APIによる自動採点

**要件**:
- 短文回答の採点
- 論述回答の採点（観点別評価）
- ストリーミング表示（SSE）
- 採点結果の保存

**受け入れ基準**:
- [ ] 解答送信後に採点結果がストリーミング表示される
- [ ] スコアとフィードバックが取得できる
- [ ] 採点結果が学習履歴に保存される

**技術的考慮事項**:
- `apps/api-ai` の既存エンドポイントを活用
- SSE対応のため `EventSource` or fetch + ReadableStream

---

#### F-08: 学習計画

**概要**: AIによる学習計画の自動生成・管理

**要件**:
- 目標設定（試験日、目標スコア）
- AIによる学習計画生成
- 日次タスク表示
- 進捗追跡
- 計画の再生成

**受け入れ基準**:
- [ ] 目標設定ウィザードが動作する
- [ ] AIが学習計画を生成する
- [ ] 日次タスクが一覧表示される
- [ ] タスク完了が進捗に反映される

---

#### F-09: 学習履歴

**概要**: 過去の学習記録の一覧・詳細

**要件**:
- 日付別学習記録一覧
- 試験別フィルタリング
- 回答詳細（問題、解答、採点結果）
- 統計サマリー

**受け入れ基準**:
- [ ] 過去の学習記録が一覧表示される
- [ ] 日付・試験種別でフィルタリングできる
- [ ] 各記録の詳細が確認できる

**オフライン対応**:
- ローカルに学習履歴を保存
- オンライン時にCosmos DBへ同期

---

#### F-10: AIアシスタント

- [ ] チャット形式で質問できる

- [ ] 会話履歴が保持される
- [ ] レート制限が正しく表示される

#### F-11: 設定

**要件**:

## 3. 非機能要件

### 3.1 パフォーマンス

| 項目 | 目標値 |
|------|--------|
| アプリ起動時間 | 3秒以内（コールドスタート） |
| 画面遷移 | 500ms以内 |
| 問題データ読み込み | 1秒以内（キャッシュあり） |
| AI採点レスポンス | 初回トークン 2秒以内 |

### 3.2 オフライン対応

| データ | オフライン利用 | 同期タイミング |
|--------|---------------|----------------|
| 問題データ | ○ 事前ダウンロード | 新規データ追加時 |
| 解答データ | ○ ローカル保存 | オンライン復帰時 |
| 学習履歴 | ○ ローカル保存 | オンライン復帰時 |
| 統計データ | △ キャッシュ表示 | 画面表示時 |
| AI採点 | × オンライン必須 | - |
| AIアシスタント | × オンライン必須 | - |

### 3.3 セキュリティ

- OAuthトークンは `expo-secure-store` で暗号化保存
- API通信はHTTPS必須
- 機微情報のログ出力禁止
- Cosmos DB接続文字列はアプリに含めない（API経由）

### 3.4 アクセシビリティ

- ダークモード対応
- フォントサイズ調整（システム設定に追従）
- タッチターゲット最小44dp
- スクリーンリーダー対応（contentDescription）

### 3.5 対応OS

- Android 8.0 (API 26) 以上
- タブレット対応（レスポンシブレイアウト）

## 4. データモデル

### 4.1 ローカルDB（SQLite）

> **注記（2026-06-12）**: 本節のスキーマは初期検討案である。実装は詳細設計書 `26_AndroidPlayDetailedDesign.md` §7（learning_events / outbox_events 等のOutbox型設計）を正とする。

```
users
├── id (PK)
├── displayName
├── email
├── avatarUrl
├── isGuest
├── createdAt
└── updatedAt

exams
├── id (PK)
├── year
├── type (AM/PM1/PM2)
├── category (SC/PM/FE/etc)
├── title
├── questionCount
├── timeLimit
└── downloadedAt

questions
├── id (PK)
├── examId (FK)
├── qNo
├── category
├── questionText
├── choices (JSON)
├── correctAnswer
├── explanation
└── downloadedAt

answers
├── id (PK)
├── questionId (FK)
├── userId (FK)
├── answer
├── isCorrect
├── score
├── feedback
├── answeredAt
└── syncedAt (NULL = 未同期)

studyPlans
├── id (PK)
├── userId (FK)
├── targetExamId
├── targetDate
├── targetScore
├── planData (JSON)
├── createdAt
└── syncedAt

chatHistory
├── id (PK)
├── userId (FK)
├── messages (JSON)
├── createdAt
└── syncedAt
```

### 4.2 同期対象コンテナ（Cosmos DB）

| コンテナ | 同期方向 | 備考 |
|----------|---------|------|
| Users | 双方向 | プロフィール更新 |
| LearningRecords | 上り | 解答・採点結果 |
| StudyPlan | 双方向 | 学習計画 |
| AiAssistantUsage | 上り | チャット履歴 |

## 6. リリース計画

### 6.1 フェーズ分け

> **注記（2026-06-12）**: 本節の期間は初期目安である。正式なスケジュールは実装WBS `docs/03_plans/android-play-implementation-wbs-20260611.md`（基準140人日・バッファ込み168人日・約34週、M0〜M5）を正とする。

| フェーズ | 内容 | 期間目安 |
|----------|------|---------|
| **Phase A: MVP** | 認証、試験一覧、午前問題、学習履歴 | 4-6週 |
| **Phase B: 午後対応** | 午後問題（短文/論述）、AI採点 | 3-4週 |
| **Phase C: 高度機能** | 学習計画、AIアシスタント、ダッシュボード | 3-4週 |
| **Phase D: 仕上げ** | オフライン同期、パフォーマンス最適化、テスト | 2-3週 |

### 6.2 クローズドβ

- Phase A-C 完了後、内部テストトラックで配布
- フィードバック収集 → 修正
- 1-2週間のテスト期間

### 6.3 一般公開

- クローズドβの問題解消後
- 本番トラックで公開
- Web版とのクロスプロモーション

## 7. 技術選定（推奨）

| カテゴリ | 技術 | 理由 |
|----------|------|------|
| フレームワーク | Expo SDK 51+ | daidoko と同一構成、EAS Build対応 |
| UI | React Native + expo-router | ファイルベースルーティング |
| 状態管理 | Zustand | 軽量、daidoko と同一 |
| データフェッチ | TanStack Query | キャッシュ、リトライ |
| ローカルDB | expo-sqlite + Drizzle ORM | オフライン対応 |
| 認証 | expo-auth-session | OAuth実装 |
| 数式 | react-native-math-view | KaTeX代替 |
| 图表 | react-native-chart-kit | ヒートマップ等 |
| ビルド | EAS Build | クラウドビルド |
| CI/CD | GitHub Actions + EAS Submit | 自動デプロイ |

## 8. リスクと対策

| リスク | 影響 | 対策 |
